# HSR Optimizer MCP 全站覆盖计划

日期：2026-10-06。基线：`feat/mcp-server` / `3f101eec`。状态：已完成两轮源码复核并修订，待 S0 浏览器逐项盘点。

目标：让 Agent 通过 MCP 完成当前网站的全部功能，包括状态管理、计算分析、外部数据、图片与展示、浏览器计算和诊断。本文接续现有 M1–M3；S0、M4–M7、M9 为全站覆盖主线，M8 为单独的可选增强。

## 1. 全覆盖如何定义

按网页功能的意图和结果验收：网页能读取的数据、修改的状态、执行的计算、生成的产物，在 MCP 中都要有可发现的入口和可验证的结果。

- 遍历所有可见页面、角色页中的组队面板（`#teams`）、隐藏的 Metadata/WebGPU 页，以及全部菜单、弹窗、抽屉和快捷操作。
- 点击、拖拽、排序、开关等交互映射为结构化操作；可调整的展示参数也要能读写。
- 截图、肖像裁剪、自定义图片、动画预览与复制保留其实际结果。分享按现有移动端截图分支接入具备能力的主机；登记平台条件，不宣称任意 MCP 客户端均支持系统分享。
- 首页、帮助、更新日志和说明文字提供资源入口；相关跳转返回可用链接或启动对应视图。
- 对不可用的运行环境返回具体原因。全站验收必须使用包含浏览器、媒体和主机适配器的完整安装，不能拿纯 Node 安装的结果宣布全覆盖。
- 保留现有 44 个工具的参数、默认值和结果兼容性。新增工具按域组织，纯参考数据优先用 resource；以功能覆盖衡量完成度。网站行为存在差异时采用新增动作入口或显式可选模式，不静默改变旧调用。

旧实施方案 §3.7 的“UI-only 不进 MCP”不再用于排除功能。旧文档保留历史记录，本计划扩大该范围。

本计划覆盖当前网站的行为。尚未在网站实现的全队全局最优搜索、游戏内自动装备等，不计入“全站”基线。

完整双向同步、多运行历史、任务跨重启续跑、分类清空和任意图表图片导出属于新增能力。它们可单独实施，但不作为网站已有功能的覆盖门槛。临时 UI 状态仍要能操作；是否持久化遵循网站原有规则。实现所需的版本校验、事务与任务查询属于技术基础，不等同于新增用户功能。

## 2. 当前基线与新发现

现有服务注册了 44 个工具、4 个固定资源和 2 个详情模板。前一轮实测完成构建与 12 套回归，日志有 519 项 PASS、0 项 FAIL；这代表现有工具的基线通过，不代表全站已经验收。

已确认的缺口包括：

- 遗器手工新增、编辑、删除及编辑器的主词条计算、部位联动和升级预览；跨角色潜力推荐与遗器库存定位。
- 独立保存完整优化表单、角色切换与退出前保存、条件修改与连招默认值联动、网页预设/重置及校验警告；已保存配装载入优化器、清空角色配装和按有效词条自动排序。
- 假想配装列表的新增、载入、覆盖、删除、全清、重算和从优化结果导入；重复检测、选中项及键变化。
- 行迹树开关及其级联规则；评分覆盖全部重置；BUFFER、HEAL、SHIELD 评分及四种模拟配置的自定义队伍；SUBSTAT_SCORE/NONE 展示模式及回退。
- 队伍删除、排序、加载；工作槽位自动补队、原子重排、清空和基准快照同步。队伍重命名已有入口。
- 全局设置与展示偏好的完整读写。
- 阿哈速度反解；效果命中的单次/累计成功概率与热图数据；计算器工作输入和跃迁规划底稿读写。
- 文件导入的“只导入遗器”分支；真正的实时扫描器接入，包括事件、资源更新和重掷结果。
- 排行榜读取、过滤、UID 排名、配装详情和时间线。
- 截图、自定义图片、裁剪、动画预览与 WebGPU 执行。
- 展示柜角色在未导入存档时的评分与模拟、假想角色预设和覆写；隐藏 Metadata 页的九个面板；入门示例存档载入。

还要修正“函数已接入但网页行为不同”的情况。例如 `warp_plan` 当前按传入 targets 计算，而网页 simple 模式会先改写快速目标。阿哈页同时提供正算和反解，现有 `calc_aha` 只暴露正算。S0 必须把这类输入转换和持久化副作用列成独立条目。

`calc_ehr` 当前仅反算所需 EHR；上一版“效果命中正算已覆盖”有误。`dps_score` 当前固定 DPS；其描述中“set_scoring_override 可改队友”与实际 schema 不符，这句描述已随本计划提交一并修正，自定义评分队伍的写入入口仍待 M6。

第二轮同时纠正了已有能力的归类：`equip_build` 支持单件装备，`save_build(overwrite=true)` 支持同名覆盖，`save_team(teamId, name)` 支持重命名，`export_save` 支持文件导出，`get_results` 支持排序/过滤/分页。`simulate_build(trace=true)` 已返回基础伤害拆分和原始增益轨迹，`analyze_build` 已有升级/对比分析，`stat_simulate` 已有假想属性计算。这些继续复用并对拍；待补齐的是网页动作、状态上下文及更完整的展示字段。详细差异见[源码复核记录](./hsr-optimizer-MCP-全站覆盖复核.md)。

## 4. 技术路线

### 4.1 共享上游行为

继续复用上游计算和持久化代码。把藏在组件、hook、确认回调中的业务动作提取为共享 service/action，让网页和 MCP 使用同一入口。

提取时保留输入规范化、默认值、迁移、角色/遗器引用更新、评分缓存失效和保存副作用。MCP domain 负责参数校验、调用和序列化，避免再维护一套业务规则。

先登记实际行为，再讨论上游问题修复。例如网页删除遗器仅卸下并删除，仍保留保存配装中的失效 ID；装备保存配装的队伍覆写目前固定 DPS。不得为了“更合理”而悄悄清理配装引用或推广到其他评分模式。必要修复作为单独的行为变更审查。

已有原始计算/覆盖参数与“执行网页动作”分开建契约：`formOverrides` 的深合并不等于网页条件编辑联动，`warp_plan` 原始目标计算不等于网页 simple 目标转换。优先新增网站动作入口或可选行为模式并保留旧默认值；无法兼容时明确版本变更。合法性校验差异另行登记，不为复刻 UI 容错而放宽现有 API 的错误检查。

### 4.2 两种运行环境

**Node 运行环境**负责存档、CRUD、表单、评分、CPU 优化、纯模拟、计算器、扫描器、排行榜数据和同步协调。

**受管理的浏览器运行环境**负责原网页组件渲染、Canvas/Spine、自定义图片、截图和 WebGPU。它由 MCP 启动并管理，使用同版本的本地页面和资源；通过明确的动作协议与 Node 交换输入、结果和状态。

浏览器执行一次任务时载入指定 revision 的存档及明确的工作状态，返回产物或计算结果。需要提交持久化变更时，由 Node 校验 revision 后落盘。浏览器渲染任务不能绕过状态协调器写入另一份存档。展示柜的未导入角色采用独立输入/缓存引用，纯评分和渲染不强制写入角色库存；“保存自定义肖像”等网页动作仍需保留其补入角色的副作用。

截图复用上游 `screenshotUtils` 的处理链，补充“返回 Blob/文件”的出口；保留字体、图片、模糊和透明背景处理。WebGPU 复用上游 GPU 入口，不把 CPU 结果包装成 GPU 结果。

剪贴板与现有平台分享分支通过本机或 MCP 客户端适配器实现。能力清单标出具体支持平台，并为图片提供文件路径、MIME 和可供客户端读取的资源。没有系统分享能力的客户端不能被报告为分享已成功。

### 4.3 状态和长任务协调

- 在现有存档世代 generation 之外引入 revision。读取、编辑、扫描导入和同步操作都带版本信息。
- 变更串行提交；多步业务操作支持快照恢复。复用已有 `captureSaveStores`，补齐新状态。
- 对长时优化、评分、GPU、浏览器导出和外部导入提供任务查询、进度、状态、取消、错误和结果引用；短同步计算继续直接返回。既有调用语义保持兼容。
- 每类任务说明取消粒度；无法中断的上游步骤在安全边界停止。
- 区分“引擎保留的前 N 行”和“全部搜索候选”，响应说明排序目标、保留数量与截断情况。全站主线对齐现有结果生命周期；多个 runId 的历史保存作为增强项。
- 对比 MCP 与网页的结果上限及缓存规则，修正实际差异。扩大输出时用分页或文件，不把大结果一次塞进工具响应。
- 明确区分存档持久化状态、会话/组件临时状态、派生缓存和外部数据，以 SaveState 与恢复路径建立白名单。仅恢复原本应持久化的状态；例如 EHR 输入、当前组队槽位、评分队伍选择和视觉调试参数不因 MCP 接入自动变成永久字段。
- 表单历史缓存、当前结果缓存及用户可见结果分别登记。内部表单快照缓存不等于网站已经提供可查询的多运行结果历史。

## 5. 分阶段实施与验收

## 7. 验证口径

### 行为对拍

同一输入存档、表单和游戏版本，分别执行网页动作与 MCP 动作，比较输出和规范化后的状态。比较要包含默认值和副作用；可排除的仅是已登记的随机 ID、时间戳等非语义字段。

旧调用回归与新增网站动作对拍分别验收。覆盖式保存、队伍重命名、文件导出、结果排序/过滤/分页及已有分析计算继续使用现有入口；不得把“重新封装”计为新功能，或为消除差异而静默改动原始工具的默认值。

### 计算对拍

区分 Node CPU、网页 CPU 和网页 WebGPU。按属性、伤害和 Float32 来源定义公差，并记录差异；不能用单一宽公差掩盖字段错误。并列候选的排序和配装身份按明确规则比较。

### 视觉验收

固定语言、字体、素材、视口和游戏数据；比较导出尺寸、布局、透明背景、关键文字/分数和视觉基线。图片准备失败必须能诊断，不能把占位图当成功产物。

### 同步与恢复

主线覆盖扫描重复事件/重连、状态并发、切档、重启、任务取消和旧 revision，并检查临时状态不被错误落盘。纳入 M8 时增加双向断线/冲突恢复、两端状态与落盘存档比较；只测 WebSocket 帧形状不足以验收。

### 完成门槛

“全站完成”需要网站基线覆盖矩阵全部通过，且完整安装上的真实浏览器、GPU、外部数据成功链路已验证。每项平台能力注明适用条件。工具数量和冒烟断言数量只作统计，不作完成门槛。源码复核不能替代 S0 浏览器盘点及最终逐项验收。
